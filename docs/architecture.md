# P-Tech Restia — 基本設計方針

## 目的
FiveMの飲食・店舗運営に関する機能を、必要な単位で導入可能なリソース群として提供する。

## アーキテクチャ
- 原則として各モジュールは独立稼働できる構成とする。
- Coreは共通機能が具体的に必要になった時点で設計し、依存を最小化する。
- モジュール間連携は可能な範囲で任意とする。
- 外部依存関係、設定項目、公開イベントやエクスポートをモジュール単位で文書化する。
- P-TechのUI・命名規則・設定形式の統一を目指す。

## リソースの命名
`ptech_restia_<module>`

## 候補機能（未確定・未実装）
| モジュール案 | 役割 |
| --- | --- |
| cooking | 調理とレシピ |
| order | 注文と受注 |
| inventory | 食材・在庫 |
| register | 会計 |
| delivery | 配達 |

## 実装前に決めること
- 対応フレームワークと既存リソースとの連携
- 権限・ジョブ・店舗ごとの設定
- アイテム管理、所持品、通貨の扱い
- UI構成とサーバー側検証
- 保存データの仕様

本資料は初期方針であり、詳細仕様は開発中に更新する。
